# codomon-photo-sync

保育園・幼稚園向けアプリ **[コドモン](https://www.codmon.com/)** に配信された自分の子どもの写真と記録を、macOS のローカルへ自動で保存するツールです。

さらに、**写真.app の顔認識**で自分の子どもが写った写真だけを抽出し、家族アルバム **[みてね](https://mitene.us/)** へ自動アップロードできます。

```text
コドモン ──> ローカル保存 ──> 写真.app ──> 顔認識で人物を抽出 ──> みてね
            (写真・記録・添付)   (iCloud同期)                  (自動アップロード)
```

## なぜ作ったか

コドモンに投稿された写真は、アプリ内でしか見られず、一枚ずつ手で保存する必要があります。退園すれば過去の記録ごと参照できなくなります。

このツールは、園から届く情報を**まるごと手元に残し**、家族と共有するところまでを自動化します。

## できること

| | 内容 |
| --- | --- |
| 写真の保存 | 投稿日ごとのフォルダへ。**EXIF に投稿日時を埋める**ので時系列で正しく並ぶ |
| 記録の保存 | 連絡帳・活動記録・お知らせ・請求情報の本文を Markdown と JSON で |
| 添付の保存 | 園だより・行事予定などの PDF・Word |
| 写真.app 連携 | アルバムへ自動取り込み。iCloud 写真経由で iPhone からも見られる |
| 人物の抽出 | 顔認識で特定の子どもだけを集めたアルバムを自動生成 |
| みてね連携 | 未アップロード分を自動送信（**みてねプレミアムが必要**） |

すべて**差分方式**で、既に処理済みのものは再取得・再送信しません。

### 対象外

**「写真共有・販売」（アルバム）の写真は取得しません。** 購入が必要な機能であり、自動化が自動課金・誤発注に直結するため、関連エンドポイントには一切アクセスしません。取得対象は無料で閲覧できるタイムライン（連絡帳・活動記録・お知らせ）に限られます。

アルバムの写真が必要な場合は、コドモン上で手動で購入・保存してください。写真.app の取り込み先アルバムに入れれば、顔認識とみてね連携は既存の仕組みがそのまま働きます。

## 動作環境

- macOS（写真.app と AppleScript を使うため必須）
- **Python 3.11 以降**（macOS 標準の `python3` は 3.9 なので、別途用意が必要です → [手順1](#1-python-311-以降を用意する)）
- コドモンの保護者アカウント
- 空き容量 1GB 程度（Chromium 約 550MB を含む）
- みてね連携を使う場合は **みてねプレミアム**（ブラウザからのアップロードが有料機能のため）

## セットアップ

導入は3ステップです。所要時間は 10〜20 分（大半は Chromium のダウンロード待ち）。

### 1. Python 3.11 以降を用意する

**ここが唯一つまずきやすい箇所です。** macOS に最初から入っている `python3` は 3.9 で、
そのままでは `setup.py` が起動時に弾きます。まず確認してください。

```bash
python3 -V
```

`Python 3.11.0` 以上と出れば、この手順は不要です。3.9 などと出た場合は、
どちらかの方法で入れてください（すでに使っているほうがあれば、それに合わせて構いません）。

```bash
# Homebrew を使う場合
brew install python@3.13

# uv を使う場合
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.13
```

入れ直したあとにターミナルを開き直し、`python3 -V` が 3.11 以降になったことを確認します。

### 2. 取得してセットアップを実行する

```bash
git clone https://github.com/Esystimsesys/codomon-photo-sync.git
cd codomon-photo-sync
python3 setup.py
```

`git` が未導入の場合、最初の `git clone` で Xcode Command Line Tools の
インストールダイアログが出ます。許可すれば以降は普通に使えます。
これを避けたい場合は、git を使わず取得することもできます。

```bash
curl -L https://github.com/Esystimsesys/codomon-photo-sync/archive/refs/heads/main.tar.gz | tar xz
cd codomon-photo-sync-main
python3 setup.py
```

対話形式で、仮想環境の作成・依存パッケージの導入・設定・コドモンの認証情報の登録・
定期実行の登録までを行います。**設定ファイルを手で書き換える必要はありません。**
途中で Chromium（約 550MB）を取得するため、初回は数分から十数分かかります。

認証情報は入力しても画面に表示されず、シェルの履歴にも残りません。macOS の
Keychain に保存され、リポジトリにも設定ファイルにも書かれません（[セキュリティ](docs/02-security.md)）。

初回の定期実行時に Keychain のアクセス許可ダイアログが出たら、**「常に許可」**を選んでください。
「許可」を選ぶとその一度きりの許可になり、次回以降の自動実行が止まります。

### 3. フルディスクアクセスを許可する（顔認識を使う場合のみ）

写真.app の顔認識結果を読むために必要です。**この許可だけは自動化できません**
（macOS の仕様上、ユーザーが手で操作する必要があります）。

システム設定 → プライバシーとセキュリティ → フルディスクアクセス を開き、
`setup.py` を実行したアプリ（ターミナル / iTerm / VS Code など）を追加して有効にします。
追加後はそのアプリを一度終了して開き直してください。

顔認識とみてね連携を使わない場合、この手順は不要です（[段階1・2](#段階的に使えます) だけなら許可なしで動きます）。

### つまずいたときは doctor

うまくいかないときは、まず状態を確認してください。足りないものと直し方が出ます。
これは macOS 標準の `python3`（3.9）でも動くので、手順1 の前に実行しても構いません。

```bash
python3 setup.py doctor
```

```text
✓ macOS 26.6.1
✓ Python 3.13.2
✓ 仮想環境と依存パッケージ
✗ フルディスクアクセスがありません
   システム設定 → プライバシーとセキュリティ → フルディスクアクセス で
   実行元（ターミナル / VS Code など）を許可してください
```

### 段階的に使えます

全部を一度に設定する必要はありません。**段階1 だけでも十分に役に立ちます。**

| | できること | 必要なもの |
| --- | --- | --- |
| **段階1** | 写真・記録・添付をローカルへ自動保存 | コドモンのアカウントだけ |
| **段階2** | 写真.app のアルバムへ自動取り込み（iPhone からも見られる） | iCloud 写真（任意） |
| **段階3** | 顔認識で子どもだけを抽出し、みてねへ自動送信 | フルディスクアクセス、みてねプレミアム |

段階1・2 は `setup.py` を実行した時点で有効です。

**段階3 を使うには**、先に写真.app の「ピープル」で子どもの顔に名前を付け、
その名前を設定の `person` に入れてください（`setup.py` が尋ねます）。空のままなら
顔認識は動かず、エラーにもなりません。みてね連携はあとから追加できます。

```bash
python3 setup.py mitene
```

### そのほかの操作

```bash
python3 setup.py            # メニューを出す
python3 setup.py schedule   # 定期実行を登録し直す（時刻を変えたとき）
python3 setup.py uninstall  # 定期実行の解除と生成物の削除
```

`uninstall` は**何を消すかを個別に尋ねます**。取得した写真は既定で残します
（コドモンから消えた古い投稿は、消すと二度と取得できないため）。

## 設定

`config.json` に個人に紐づく値をまとめています（Git 管理外）。`setup.py` が作るので、
手で書く必要はありません。あとから変えたいときだけ直接編集してください。

| キー | 内容 |
| --- | --- |
| `person` | 写真.app のピープルで付けた名前。この人物の写真だけを抽出する（空なら顔認識を使わない） |
| `album` | 写真.app に作る全写真用アルバムの名前 |
| `person_album` | 人物別アルバムの名前（省略時は「アルバム名（人物名）」） |
| `save_root` | 写真と記録の保存先 |
| `days_to_check` | 毎回さかのぼる日数 |
| `mitene_scope` | みてねの公開範囲ボタンの表示名 |
| `face_min_px` | 顔の幅がこれ以上なら採用（既定 25。配信画像は幅500px固定） |
| `face_min_ratio` | 大きく写っていても、写真内で最大の顔のこの比未満なら脇役として除外（既定 0.6） |
| `face_main_ratio` | 顔が小さくても、写真内で最大の顔のこの比以上なら採用（既定 1.0） |
| `face_max_people` | 上の救済を使う条件。写真内の検出人数の上限（既定 0＝無制限） |
| `job_labels` | 死活監視の対象。`setup.py` が書くので触らない |

## 保存されるもの

```text
~/Pictures/codomon/2026-08-05/
├── 123456789-IMG_0001.jpeg   写真（EXIF に投稿日時を埋めてある）
├── 添付/
│   └── 12345-8月のおたより.pdf
├── 記録.md                    連絡帳・活動記録・お知らせ・請求の本文
└── posts.json                 生データ
```

`記録.md` は写真への相対リンクを含むので、Markdown ビューアで開けば本文と写真を一緒に読めます。

## 定期実行

launchd で 3 つのジョブを動かします。

| ジョブ | 時刻 | 処理 |
| --- | --- | --- |
| `com.codomon-photo-sync.sync` | 17:30 / 21:00 | コドモンから取得 → 写真.app へ取り込み |
| `com.codomon-photo-sync.person` | 7:00 / 13:00 / 19:00 / 22:00 | 顔認識の反映 → みてねへアップロード |
| `com.codomon-photo-sync.healthcheck` | 8:00 / 23:00 | 上 2 つが止まっていないか確認し、異常なら通知 |

取得を1日2回にしているのは、夕方以降に投稿された分を当日中に拾うためです。2つのジョブは排他ロックを共有するため、同時刻に重ならないよう時刻をずらしています。

写真.app の顔解析は取り込み直後には終わらず、Mac がアイドルのときに進みます（実測で最短 50 分、多くは数時間）。そのため人物の抽出だけを小刻みに走らせ、解析が終わり次第すぐ反映されるようにしています。

**この仕組みは静かに止まります。** launchd がプログラムを起動できずに終了した場合、ログが1行も残らないため、ログを見に行っても異常に気づけません。実際に3回止まり、最長29時間気づけませんでした。そのため死活監視を独立したジョブとして分けています。

## 構成

| ファイル | 役割 |
| --- | --- |
| `setup.py` | 導入・設定・撤去。これだけシステムの python3 で動く |
| `sync_photos.py` | 本体。取得・記録保存・写真.app 取り込み |
| `export_person.py` | 顔認識で人物別アルバムを生成 |
| `mitene_upload.py` | みてねへ未アップロード分を送信 |
| `run_person_tasks.py` | 上 2 つをまとめて実行（1日4回のジョブ用） |
| `common.py` | 設定読み込み・排他ロック・アトミック書き込み・**人物の判定**（アルバムとみてねで共通） |
| `healthcheck.py` | 定期実行が止まっていないかを監視し、異常なら通知 |

## 制約と注意

**画像は 500px が上限です。** コドモンの無料閲覧で配信される画像の仕様で、回避できません。このため顔認識の識別率も **2 割程度**に留まります（顔の幅の中央値が 33px しかないため）。原寸は「写真共有・販売」の購入でのみ入手できますが、**このツールはその購入フローには触れません**（[対象外](#対象外)）。

**コドモンの内部APIを利用しています。** 公開APIではないため、予告なく仕様が変わる可能性があります。利用規約に自動化を明示的に禁じる条項はありませんが、自分のアカウントで自分の子の記録を取得する用途に限って使ってください。

**みてねのログインは自動化していません。** reCAPTCHA と 2 要素認証があり、これを迂回する実装は運営の意思に反すると判断したためです。ログインだけ手動で行い、以降のアップロードを自動化しています。セッションはアクセスのたびに延長されるため、定期実行が動いていれば再ログインはほぼ不要です。

## 開発時の検証

```bash
.venv/bin/python -m unittest discover -s tests -v
```

回帰テストは一時ディレクトリとモックを使い、コドモン・みてねへの通信、写真.appの変更、launchdへの登録を行いません。
