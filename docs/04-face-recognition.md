# 顔認識による人物別アルバム

写真.app の顔認識を使い、特定の人物（config.json の person で指定）が写った写真だけを集めたアルバムとフォルダを作る。みてねなど他サービスへアップロードする際に、691枚から探す手間をなくすのが目的。

実行は [export_person.py](../export_person.py)。1日4回のジョブ（`run_person_tasks.py`）に組み込み済み。本体(17:30)からも呼ばれる。

## 結果（2026-08-10 時点）

| | 枚数 | 割合 |
| --- | --- | --- |
| コドモンアルバム全体 | 691 | — |
| 顔が検出された写真 | 672 | — |
| **指定した人物と識別された写真** | **153** | **22.1%** |

検出された顔は全体で2,473個。うち対象人物は150個（6%）で、残りは園の他の子どもたち。

### 識別率が22%に留まる理由

**画像が500px上限だから**。顔の幅の中央値は33pxしかなく、本人判定の実用下限とされる60pxを超えるのは21%だけだった（Vision frameworkで実測）。この21%という数字が識別率22.1%とほぼ一致しており、**解像度がそのまま識別率の上限になっている**。

アルゴリズムを変えても改善は見込めない。原寸を得るには「写真共有・販売」の購入が必要（[01-api.md](01-architecture.md) 参照）。

## 顔解析はいつ実行されるか

**取り込み直後には解析されない。** macOSの `photoanalysisd` が、Macが電源接続かつアイドルのときに少しずつ進める。

実測では、680枚を取り込んだ直後は10枚しか解析されておらず（`photoanalysisd` のCPU時間は2時間で5秒）、一晩放置して全680枚が完了した。

このため**新着写真がすぐ人物アルバムに入ることはない**。数時間〜数日遅れる。

### 日付ベースの処理にしてはいけない

「前日ダウンロードした分を処理する」という設計だと、その時点では未解析なので取りこぼし、その後解析されても二度と見に行かない。

`export_person.py` は**毎回全期間を再評価**し、アルバムに無いものだけ追加する。解析がいつ完了しても次の実行で拾われる。全期間評価でも3〜4秒で終わる。

## 出力

| 出力先 | 内容 |
| --- | --- |
| 写真.app人物別アルバム | 該当写真のアルバム。iCloud経由でiPhoneからも見られる |
| `~/Pictures/codomon-person/` | 同じ写真のローカルコピー。**定期実行では `--no-copy` を渡すため更新されない**（手動で `export_person.py` を引数なしで実行したときのみ） |

### アルバムに入れても写真は二重にならない

アルバムは**写真の実体ではなく参照の集合**。153枚を2つ目のアルバムに入れても、ライブラリのアセット数（8,304）も容量（21G）も変化しないことを実測で確認済み。iCloudの使用容量も増えない。

ただし**AppleScriptの `import` は使ってはいけない**。`import` は新規取り込みなので実体が増える。既にライブラリにあるアイテムを `add` でアルバムに参照登録すること。

## 制約

**iCloud共有アルバムへの自動投稿はできません。** AppleScript・PhotoKit・ショートカットのいずれからも書き込めず、投稿するとファイル名も日時も変わるため送信済みの判定もできません。検討のうえ不採用としました。

**写真.appの操作には制限があります。** AppleScript から写真の削除やアルバムからの除外はできません。アルバム内の重複を解消したい場合は、重複を除いた新しいアルバムを作って入れ替えます（ライブラリの写真は削除せずに済みます）。

**フルディスクアクセスが必要です。** 顔認識の結果は写真.appのライブラリDBから読むため、実行元にフルディスクアクセスを与えてください。
