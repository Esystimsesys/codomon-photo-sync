# 仕組み

## コドモンからの取得

コドモンの保護者向けWeb版（`parents.codmon.com`）は SPA で、内部的に REST API を叩いています。本ツールはブラウザ（Playwright）でログインし、**そのセッションで内部APIを呼んで**投稿一覧を取得します。

画面の DOM をスクレイピングする方式も検討しましたが、次の理由で API 方式を選びました。

- 画面のレイアウト変更に影響されない
- 日付・本文・写真URLが構造化データで正確に取れる
- ページングが明示的で、取りこぼしを検出しやすい

**公開APIではありません。** 予告なく仕様が変わる可能性があり、その場合はツールが動かなくなります。エンドポイントやパラメータの詳細は、運営が想定した使い方ではないため本リポジトリには記載していません。

## 認証

| 項目 | 方式 |
| --- | --- |
| 認証情報の保管 | macOS Keychain（[02-security.md](02-security.md)） |
| ログイン | Playwright でフォームを操作 |
| セッション | `storage_state.json` に保存して再利用 |
| 認証状態の判定 | **API のステータスコード**（DOM の文言に依存しない） |

セッションが切れていれば自動で再ログインします。再ログイン時は Cookie だけでなく **localStorage も消してから**やり直します（消さないと SPA が「ログイン済み」と誤認してログイン画面を出さないため）。

## 写真の日付

配信される画像は**リサイズの過程で EXIF が完全に除去されています**。そのまま保存すると写真.app が「取り込んだ日」を撮影日として扱い、全写真が実行日に固まってしまいます。

これを避けるため、ダウンロード時に投稿日時を EXIF (`DateTimeOriginal`) へ書き込んでいます。同じ日の中でも投稿順に並ぶよう、日付だけでなく時刻も入れています。

## 差分の判定

| 対象 | 判定方法 |
| --- | --- |
| 写真・添付 | 保存先にファイルがあればスキップ（HTTPリクエストも行わない） |
| 記録 | 毎回上書き再生成（通信は増えず、園側の修正に追随できる） |
| 写真.app 取り込み | アルバム内のファイル名と突き合わせ |
| みてね送信 | **ローカル台帳**（相手側のデータは参照しない） |

写真のファイル名は投稿ID付きで一意なため、名前の一致だけで既取得を判定できます。ハッシュ計算は不要です。

みてねだけ台帳方式なのは、**アップロードすると相手側でファイル名も日時も変わる**ため、送信済みかどうかを相手のデータから判定できないからです。

## 画像の解像度

**500px が上限**です。無料で閲覧できる範囲の仕様で、リクエストパラメータを変えても取得できません。原寸は「写真共有・販売」の購入フローでのみ入手できます。

この制約は顔認識の精度に直結します（[04-face-recognition.md](04-face-recognition.md)）。

## 保存対象

園から届く情報は**すべて保存**します。

| 種別 | 内容 |
| --- | --- |
| 連絡帳 | 体温・食事・睡眠・家庭からの連絡 |
| 活動記録 | その日の活動の本文と写真 |
| お知らせ | 園からの通知。PDF等の添付を含む |
| 請求情報 | 月々の請求明細 |

当初は写真が付く種別だけを対象にしていましたが、**連絡帳がまるごと抜けていました**。保存対象を「写真の有無」で決めたのが誤りでした。退園すれば過去データは参照できなくなるため、取捨選択せず全部残す方針にしています。
