# 仕組み

## コドモンからの取得

コドモンの保護者向け Web 版（`parents.codmon.com`）は SPA で、内部で REST API を呼んでいる。本ツールはブラウザ（Playwright）でログインし、**そのセッションで内部 API を呼んで**投稿一覧を取得する。

画面の DOM をスクレイピングする方式も検討したが、次の理由で API 方式を選んだ。

- 画面のレイアウト変更に影響されない
- 日付・本文・写真 URL が構造化データで正確に取れる
- ページングが明示的で、取りこぼしを検出しやすい

**公開 API ではない。** 予告なく仕様が変わる可能性があり、その場合はツールが動かなくなる。運営が想定した使い方ではないため、エンドポイントやパラメータの詳細はドキュメントにまとめていない（呼び出しは `sync_photos.py` にある）。

## 認証

| 項目 | 方式 |
| --- | --- |
| 認証情報の保管 | macOS Keychain（[02-security.md](02-security.md)） |
| ログイン | Playwright でログインフォームを操作する（`sync_photos.py` の `ensure_login()`） |
| セッション | `storage_state.json` に保存して再利用する |
| 認証状態の判定 | **API のステータスコード**（DOM の文言に依存しない） |

セッションが切れていれば自動で再ログインする。再ログイン時は Cookie だけでなく **localStorage も消してから**やり直す（消さないと SPA が「ログイン済み」と誤認し、ログイン画面を出さないため）。

## 写真の日付

配信される画像は、**リサイズの過程で EXIF が完全に除去されている**。そのまま保存すると写真.app が「取り込んだ日」を撮影日として扱い、全写真が実行日に固まってしまう。

これを避けるため、ダウンロード時に投稿日時を EXIF (`DateTimeOriginal`) へ書き込む。時刻には投稿の配信日時（`delivery_start_datetime`）を使うので、同じ日の中でも投稿順に並ぶ。EXIF を書き込めなかった写真は保存せず、次回に取り直す。

## 差分の判定

| 対象 | 判定方法 |
| --- | --- |
| 写真・添付 | 保存先にファイルがあればスキップする（HTTP リクエストも行わない） |
| 記録 | 全施設・全ページの取得に成功してから、まとめて再生成する（園側の修正に追随できる） |
| 写真.app への取り込み | アルバム内のファイル名と突き合わせる |
| みてねへの送信 | **ローカルの台帳**で判定する（相手側のデータは参照しない） |

写真のファイル名は投稿 ID 付きで一意（`123456789-IMG_0001.jpeg`）なため、名前の一致だけで取得済みかを判定できる。ハッシュ計算は要らない。

日別の記録には全施設の投稿をまとめる。途中のページ取得に失敗した場合や、ページ数の上限に達しても続きがある場合は異常終了し、保存済みの記録をそのまま残す。

みてねだけ台帳方式なのは、**アップロードすると相手側でファイル名も日時も変わる**ため、送信済みかどうかを相手のデータから判定できないからである。

## 画像の解像度

**幅 500px が上限**。無料で閲覧できる範囲の仕様で、リクエストのパラメータを変えても大きい画像は取得できない。原寸は「写真共有・販売」の購入フローでのみ入手できる。

この制約は顔認識の精度に直結する（[04-face-recognition.md](04-face-recognition.md)）。
