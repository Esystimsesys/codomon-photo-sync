# おむかえフォト 開発メモ

利用者向けの説明はすべて [README](../README.md) にまとめる。ここには、作りの判断と開発の手順だけを書く。

## 署名

Developer IDによる署名・Appleの公証は行わない。配布版は毎回同じ自作の証明書で署名し、「写真」アプリの操作と写真ライブラリの許可を更新後も引き継ぐ。キーチェーンの確認は、Team IDがないため更新ごとに出る（理由は[版番号とリリース](02-release.md)）。通常のテストはアドホック署名にする。署名がないとダウンロード後に「壊れているため開けません」と表示されるため、どちらもアプリ全体の署名を検証する。Mac全体のGatekeeperを無効化する手順は案内しない。署名用の鍵と手順は[版番号とリリース](02-release.md)を参照。

## 仕様の補足

- 自動送信の対象は、自動送信をオンにした日（設定の`autoSendFrom`）以降にコドモンに届いた写真。届いた日は配信開始の日時（なければ投稿の日時）で判定する。園が記録に付けた日付は届いた日と一致しないことがある（行事のお知らせは最大32日先の日付で届く）ため使わない。届いた日を記録していない古いデータは記録の日付で判定する。開始日のない古い設定は、その版を初めて開いた日を開始日にする。
- 送信ボタンを押した後に完了を確認できなかった写真は「確認が必要」にし、自動で再送しない。
- 「写真」アプリの個別の取り込み警告は、ほかの写真の送信を妨げない。顔解析全体が失敗した場合は、古い自動判定で送らない。
- みてねのログインは、自動操作のブラウザではなくアプリの普通の画面で行う。PCアップローダーのログインは reCAPTCHA で機械によるログインを防いでおり（[公式ヘルプ](https://help.family-album.com/hc/ja/articles/360038264834)）、2026-10-16 には自動操作のブラウザからのログインが「セキュリティ上の問題」で止められた。画面は使い捨てのセッションでみてねのページだけを開き、ログイン後の Cookie だけを、ほかのログイン情報と同じく暗号化して保存する。ブラウザの名乗り（User-Agent）は変えない。写真の送信は今までどおり自動操作のブラウザで行う。コドモンのログインは自動操作のブラウザのまま。
- コドモンの取り込みは、通信を試みた時点で回数に数える。再起動や時刻の変更では戻さず、Macの暦日が変わると0回に戻す。最初のログインの確認（`/my/`、1回だけの軽い通信）で止まったときは数えない。その応答が5xx・429なら「接続できません」としてログインが必要の印を立てず、それ以外は再ログインを案内する。どちらもHTTP番号を添える（2026-10-21 の全サービス停止で、停止を再ログインと表示していたため）。401 のときは、ログイン画面が localStorage に残した再発行用トークンで `refresh_session` を1回だけ呼び、通れば `/my/` を確かめ直して続ける。コドモンの画面が 401 で行うのと同じ手順。トークンは再発行のたびに入れ替わるので、受け取ったらすぐ保存する。再発行が通ったときは、新旧トークンの期限（JWT のとき）を `archive.sqlite` の `codmonRefresh` に残す。
- 自動同期は、指定した時刻から回ごとにランダムに0〜4分遅らせて始める。初期値の時刻のまま使う人が、同じ分にコドモンへ問い合わせないため。遅らせる分数はその回で一度だけ決めて `syncDelay` に残し、再起動しても決め直さない。Macごとに固定で遅らせる案は、指定した時刻なのに毎日決まって遅れて見えるので採らない。スリープから戻ったときに、遅らせた分を過ぎていればすぐに始める（戻る時刻はもともと散らばる）。
- 同期で確かめる期間は、前回の同期の7日前から今日まで（失敗して残った期間があれば、そこまで広げる）。2026-10-29 に2023年からの全記録（連絡帳・お知らせ829件、活動記録120件）で、記録の日付が届いた日よりさかのぼったものがないことを確かめた。以前は30日前から確かめていた。
- 成長記録は、同期のたびに子どもごとに `member_growths/` を年度単位（4月〜翌3月、コドモンの画面と同じ）で取る。子どもに施設ごとの member_id が複数あれば、まとめて `relation_id[]` に渡す。初めては園の記録のいちばん古い日（入園の頃）から、成功した後は同期の期間にかかる年度だけを取る。取った年度の記録は置き換えて、園での修正・削除を反映する。失敗しても写真・記録の同期済みの扱いは変えず、全期間の取り込みは成功するまで次の同期でやり直す。グラフは、身長（左の縦軸）と体重（右の縦軸）を色分けして1つに重ねる（2026-11-01 ユーザー指定。コドモンの画面と同じ形）。2本の縦軸は目盛りの位置をそろえ、それぞれの軸の上に線の色と名前を出して、どの線がどちらの軸かを色だけに頼らない。グラフは表示幅に合わせて描き直し、文字が縮まないようにする。胸囲・頭囲は関心が低いので、閉じた欄に別々のグラフと表で入れる。
- 「写真」アプリへの取り込みは、取り込み先のアルバムにある写真のファイル名で取り込み済みかを判定する。
- 顔認識で子どもが見つからない写真は、「写真」アプリが顔の解析を終えたもの（`ZFACEANALYSISVERSION` が0より大きい）だけ「写っていない」とし、取り込み前・解析前のものは「顔認識の結果待ち」にする。解析の状態を持たないライブラリでは、これまでどおり「写っていない」とする。
- 写真画面のタブは状態で分ける：送る候補（自動送信では送信待ち）・顔認識待ち（顔認識の結果待ちで、自分で選んでも外してもいない写真。ある間だけ出す）・送らない（顔認識で選ばれなかった写真、自分で外した写真、送らないことにした写真）・送信済み。顔認識待ちは送るかどうかがまだ決まっていないので、「送らない」に入れない。みてねを使わないときは「アルバムに入れる」「入れない」。
- コドモンの動画（お知らせに付く）は、写真と同じ扱いにする（写真の一覧・「写真」アプリへの取り込み・顔認識・みてねの送信）。コドモンで変換が済み再生用URLがあるものだけ、配信（HLS・MPEG-TS）を取得してmacOS付属の`avconvert`で再エンコードせずMP4にし、投稿日を動画の作成日時に書き込む。暗号化された配信は保存しない。ファイル名は元の名前とサイズ（例：`IMG_0665-130077733.mp4`）で、園が期間を延長して再掲しても同じ動画として扱い、最初に保存した場所を使う（`.video-sources`）。一覧の画像はコドモンのサムネイルを`.video-thumbnails`に保存し、なければ仮の画像を出す。保存できなかった動画も、ファイル名・サイズ・再生期限を記録に残す。みてねはPCアップローダーで1本10分までなので（[公式ヘルプ](https://help.family-album.com/hc/ja/articles/360038720993)）、10分を超える動画は送らず、自動送信では結果の文に本数を出し、手動で選んだときは理由を示して止める。
- 「園の記録」は記録ごとに本文のあとへ写真・動画（すべて）・添付を並べ、本文は長ければ書き出しだけにする。記録に付いた写真は、記録の`photos`（写真のid。別の記録と共有された写真も含む）と、写真の`postId`の両方からたどる。`photos`のない以前の記録は、次に取り込み直すまで`postId`だけで表示する。添付の一覧画像は、画像ならそのまま、それ以外はmacOSのQuick Lookのサムネイル（`nativeImage.createThumbnailFromPath`）を使う。

## データの保存

- 成長記録：保存先の`成長記録/<名前>.csv`（月・身長・体重・胸囲・頭囲。コドモンの記録は月ごとで日付は毎月1日なので、画面とCSVは月で示す（`2026-10`）。Excelで文字化けしないようBOM付き）と、`成長記録/元データ/<名前>-<年>年度.json`（コドモンの応答のまま）。アプリの表示には`archive.sqlite`の`growths`を使う。
- 写真・添付・記録：設定した保存先。記録は`日付/記録/<投稿識別子>.json`と`.md`に保存する。投稿単位のため、一部の取得失敗で別施設・別月の既存記録を消さない。
- 写真の日付：投稿日をEXIFへ書き込む。日付が不明な画像は原本を`unknown-date`へ保存し、「写真」アプリへの自動取り込みを保留する。
- 設定・写真の状態・送信台帳：Electronの`userData`配下`archive.sqlite`。
- ログイン状態：`userData/sessions/*.enc`。Electron safeStorage（MacではKeychain）で暗号化する。パスワードそのものは保存しない。暗号化が使えない場合は平文保存せずエラーにする。
- みてねのログイン状態は、連携が有効なとき、選別の更新で1日1回確認・更新する。
- 写真ライブラリDBは読み取り専用で開き、WALを含む最新状態を参照する。顔認識は非公開のDB形式に依存するため、OSの更新で対応が必要になることがある。
- 移行用ファイル（設定の「別のMacへ移す」）は、設定・送信台帳・手動の選択をJSONにしたもの。ログイン状態は含めない。読み込み先のMacの記録を優先して統合する。

## 開発・試験

```bash
cd desktop
npm ci
npm run browser:install
npm run typecheck
npm test
npm run test:ui
npm run test:native
npm start
```

`npm run demo`は隔離された一時データでElectronを起動する。`npm run dev -- --port 4179`は架空データだけのブラウザプレビュー。どちらもコドモン・みてねへの実送信はしない。実アプリの操作はpreloadの限定APIからメインプロセスへ渡し、レンダラーのNodeアクセス・任意ナビゲーション・任意IPCは許可しない。

## 配布ファイル

```bash
npm run package:signed
```

`desktop/release/`へDMGとZIPが生成される。Playwright用ブラウザを同梱するためサイズは大きめ。

`.github/workflows/desktop.yml`はApple SiliconとIntelの各Macランナーで試験・パッケージを作る。`v0.1.1`のようなタグを push すると、両方のDMG・ZIPを添付した下書きのGitHub Releaseまで作る。公開は下書きを確認してから手で行う。版番号の付け方と手順は[版番号とリリース](02-release.md)を参照。

Appleの公証、完全自動更新、Windows版、iPhone管理は初版に含めない。更新ボタンはGitHub Releasesの新しい版を確認し、ダウンロードページへ案内する。
