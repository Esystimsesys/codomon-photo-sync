# Mac用ツール「おむかえフォト」

**コドモンの写真と記録をMacに保存し、みてねへ送るツール**です。保護者が個人で作った非公式のツールで、コドモン・みてねの運営会社とは関係ありません。

初版はMac向け。iPhoneからの管理は別途検討、Windows版は顔認識などOS固有部分の置き換えを評価してから対応します。

## 利用者の導入

1. GitHub ReleasesからMacのCPUに合うDMGをダウンロードします。`arm64`はApple Silicon、`x64`はIntel向けです（公開されたファイルだけが配布対象です）。
2. 「おむかえフォト」をアプリケーションフォルダへ移し、起動します。
3. 「コドモンにログイン」で開いた専用ブラウザでログインします。パスワードや認証コードはブラウザに入力します。
4. 保存先と、必要ならMacの「写真」アプリ・みてねを設定します。ほかのソフトのインストールは不要です。
5. 「はじめる」→ホームの「今すぐ同期」で取得します。自動同期・ログイン時の起動は設定から有効にできます。

試用版はDeveloper IDによる署名・Appleの公証を行いません。開発元を確認できない警告が出た場合は、配布元を確認してからシステム設定の「プライバシーとセキュリティ」でこのツールを個別に許可します。Mac全体のGatekeeperを無効化する手順は使いません。[Appleの説明](https://support.apple.com/ja-jp/102445)

Macの「写真」アプリへの初回取り込み時にはオートメーションを許可します。顔認識を使う場合は、Macの「写真」アプリで子どもに名前を付け、「フルディスクアクセス」で**おむかえフォト**を許可します。きょうだいは設定で全員を登録すると、誰か一人でも写った写真が候補になり、子どもごとのアルバムにまとまります。顔解析が完了するまでは候補が少ない場合があります。顔認識を使わず、写真を手動で選ぶこともできます。

みてねへの送信には、有料の「プレミアムFamily」または「プレミアムFamily Pro」の契約が必要です。無料版・プレミアムOneでは使えません（[みてねの公式プラン比較](https://mitene.us/premium)）。ログイン画面・認証コード・不正ログイン対策は人が操作します。写真共有・販売の画像は取得しません。

## 送信の選択

- **確認してから送る（初期値）**：写真画面で送りたい写真にチェックを付け、公開範囲を確認して送信。
- **自動で送る**：同期・顔認識の更新時に、選ばれた未送信の写真を送信。対象は「自動で送る」にした日以降にコドモンに届いた写真だけで、それより前の写真は自動では送りません。初めて使う人の過去の写真が、最初の同期でまとめて送られないようにするためです。届いた日は、コドモンの配信開始の日時（なければ投稿の日時）で判定します。園が記録に付けた日付は、さかのぼることがあるため使いません。届いた日を記録していない古いデータは、記録の日付で判定します。それより前の写真で選ばれたものは、ホームと写真画面の「みてね自動送信設定前の写真」のお知らせから、見て送るか「送らない」にできます。「自動で送る」にした日は設定に残り、オンのまま設定を変えても動きません。開始日のない古い設定は、この版を初めて開いた日を開始日にします。
- 写真画面のタブは、確認してから送るなら「送る候補／未選択／送信済み・送らない」、自動で送るなら「送信済み・送らない／未選択／送信待ち」、みてねを使わないなら「まとめる写真／未選択」。要確認・自動送信設定前の写真・みてねのログインは、あるときだけタブの上にお知らせとして出します。「すべて表示」で全部の写真を見られます。
- 写真ごとの「選択する」「外す」は、後日の顔認識より優先して保持。「自動に戻す」で、顔認識の結果に従います。顔認識もみてねも使わない場合、写真画面は一覧表示だけになります。
- すでに別の方法で共有した過去写真は、写真画面の「すでにみてねに送った写真を登録する」で「送らない」にできます。実送信の履歴とは区別します。
- 送信ボタンを押した後に完了を確認できなかった写真は「送信できたか確認が必要な写真」としてお知らせに出します。自動再送しません。みてねで確認して「届いていた（送信済みにする）／届いていない（未送信に戻す）／送らない」を選びます。チェックした写真は、まとめて選べます。
- Macの「写真」アプリの個別取り込み警告はほかの正常な写真の送信を妨げません。顔解析全体が失敗した場合は、古い自動判定で送らず、手動送信を利用できます。

ウィンドウを閉じてもメニューバー（双葉のアイコン）に常駐します。終了するにはメニューの「終了」または⌘Qを使います。Macの電源オフ・スリープ中は処理しません。同期の時刻は設定の「自動同期」、顔認識の更新時刻は「Macの「写真」アプリ」の詳細設定で変更でき、変更は自動で保存されます。初期値は同期が17:30・21:00、顔認識の更新が7:00・13:00・19:00・22:00です。時刻をすべて削除すると、その自動処理は止まります。復帰時は直近の未実行枠を一度実行します。長く停止していても最終取得からの期間を遡ります。コドモンの取り込みは「今すぐ同期」・期間指定を含め1日最大2回です。通信を試みた取り込みは失敗しても回数に含まれ、再起動や時刻変更ではリセットされません。Macの暦日が変わると再び取り込めます。

## データの保存

- 写真・添付・記録：設定した保存先。新しい記録は`日付/記録/<投稿識別子>.json`と`.md`に保存します。投稿単位のため一部の取得失敗で別施設・別月の既存記録を消しません。
- 写真の日付：投稿日をEXIFへ書き込みます。日付が不明な画像は原本を`unknown-date`へ保存し、Macの「写真」アプリへの自動取り込みを保留します。
- 設定・写真の状態・送信台帳：Electronの`userData`配下`archive.sqlite`。このツールから端末外の自前サーバーへ送信しません。
- ログイン状態：`userData/sessions/*.enc`。Electron safeStorageを使用し、MacではKeychainに基づく暗号化を行います。パスワードそのものはこのツールに保存しません。利用可能な暗号化がない場合は平文保存せずエラーにします。
- みてねの有効なログイン状態は、連携有効時の選別更新で1日1回確認・更新します。失効した場合は再ログインします。
- 写真ライブラリDBは読み取り専用で開き、WALを含む最新状態を参照します。顔認識は非公開DB形式に依存するため、OS変更で対応が必要になる場合があります。

バックアップ時はおむかえフォトを終了してから、写真保存先と`userData`全体をコピーします。ログイン状態は別のMacでは再利用できない場合があり、その場合は再ログインします。おむかえフォトを削除しても写真・台帳は自動削除しません。

## 開発・試験

```bash
cd desktop
npm ci
npm run browser:install
npm run typecheck
npm test
npm run test:ui
npm run test:native
npm start
```

`npm run demo`は隔離された一時データでElectronを起動します。`npm run dev -- --port 4179`は架空データだけのブラウザプレビューです。どちらもコドモン・みてねへの実送信はしません。実アプリの操作はpreloadの限定APIからメインプロセスへ渡し、レンダラーのNodeアクセス・任意ナビゲーション・任意IPCは許可しません。

## 配布ファイル

```bash
npm run package:mac
```

`desktop/release/`へDMGとZIPが生成されます。Playwright用ブラウザを同梱するためサイズは大きめです。

`.github/workflows/desktop.yml`はApple SiliconとIntelの各Macランナーで試験・パッケージを作ります。`v0.1.1`のようなタグを push すると、両方のDMG・ZIPを添付した下書きのGitHub Releaseまで作ります。公開は下書きを確認してから手で行います。版番号の付け方と手順は[版番号とリリース](02-release.md)を参照してください。

署名・公証、完全自動更新、Windows版、iPhone管理は初版に含めません。更新ボタンはGitHub Releasesの新しい版を確認し、ダウンロードページへ案内します。

## 初版の検証結果（2026-10-02）

- TypeScript型検査、単体・移行・サービス試験51件、Playwright画面試験17件、既存Python回帰試験31件が成功。
- サブエージェントによる実装レビューを実施。増分取得の欠落、移行時の台帳競合、送信結果不明時の再送、アルバム置き換えの失敗経路を修正・検証。
- Apple SiliconのElectron本体と配布アプリで起動、限定preload、設定保存と再起動、デモ表示を確認。同梱ブラウザの起動も確認。
- 実コドモンの読み取り・繰り返し取得による件数と識別子の一致、みてねのアップロード画面の読み取り、実写真ライブラリの読み取りと旧Python版との選別一致を確認。
- 実みてねへの投稿と実写真ライブラリへの書き込みは行っていません。送信・アルバム変更の失敗経路は模擬アダプターで検証しています。Intelランナーでの実行、署名・公証、GitHub Releases公開は未実施です。
