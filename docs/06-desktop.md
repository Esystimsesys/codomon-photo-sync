# Mac用ツール「おむかえフォト」

**コドモンの写真と記録をMacに保存し、みてねへ送るツール**です。保護者が個人で作った非公式のツールで、コドモン・みてねの運営会社とは関係ありません。

Python版とは別のツールとして動作します。初版はMac向け。iPhoneからの管理は別途検討、Windows版は顔認識などOS固有部分の置き換えを評価してから対応します。

## 利用者の導入

1. GitHub ReleasesからMacのCPUに合うDMGをダウンロードします。`arm64`はApple Silicon、`x64`はIntel向けです（公開されたファイルだけが配布対象です）。
2. 「おむかえフォト」をアプリケーションフォルダへ移し、起動します。
3. 「コドモンにログイン」で開いた専用ブラウザでログインします。パスワードや認証コードはブラウザに入力します。
4. 保存先と、必要なら写真.app・みてねを設定します。PythonやNode.jsのインストールは不要です。
5. 「保存してはじめる」→ホームの「今すぐ同期」で取得します。自動同期・ログイン時の起動は設定から有効にできます。

試用版はDeveloper IDによる署名・Appleの公証を行いません。開発元を確認できない警告が出た場合は、配布元を確認してからシステム設定の「プライバシーとセキュリティ」でこのツールを個別に許可します。Mac全体のGatekeeperを無効化する手順は使いません。[Appleの説明](https://support.apple.com/ja-jp/102445)

写真.appへの初回取り込み時にはオートメーションを許可します。顔認識を使う場合は、写真.appで対象人物に名前を付け、「フルディスクアクセス」で**おむかえフォト**を許可します。顔解析が完了するまでは候補が少ない場合があります。顔認識を使わず、写真を手動で選ぶこともできます。

みてねへの送信は、パソコンからアップロードできる契約が必要です。ログイン画面・認証コード・不正ログイン対策は人が操作します。写真共有・販売の画像は取得しません。

## 送信の選択

- **確認してから送る（初期値）**：写真画面で候補を確認し、選んだ写真と公開範囲を確認して送信。
- **自動で送る**：同期・顔判定更新時に未送信の候補を送信。設定時に過去の未送信候補も対象になることを確認します。
- 写真ごとの「候補に入れる」「候補から外す」は、後日の顔認識より優先して保持。顔認識もみてねも使わない場合、写真画面は一覧表示だけになります。
- すでに別の方法で共有した過去写真は、写真画面の「このツールを使う前に送った写真を登録する」で「送信不要」にできます。実送信の履歴とは区別します。
- 送信ボタンを押した後に完了を確認できなかった写真は「要確認」に移します。自動再送しません。みてねで確認して「届いていた（送信済みにする）／届いていない（未送信に戻す）／送らない（送信不要にする）」を選びます。
- 写真.appの個別取り込み警告はほかの正常な写真の送信を妨げません。顔解析全体が失敗した場合は、古い自動判定で送らず、手動送信を利用できます。

ウィンドウを閉じてもメニューバー（「おむかえ」）に常駐します。終了するにはメニューの「終了」または⌘Qを使います。Macの電源オフ・スリープ中は処理しません。起動中は17:30・21:00に取得、7:00・13:00・19:00・22:00に選別を更新し、復帰時は直近枠を一度実行します。長く停止していても最終取得からの期間を遡ります。

## 旧Python版からの移行

1. はじめの設定（写真を取り込む前）の「旧版（Python版）から引き継ぐ」で「旧版のフォルダを選ぶ」を押し、旧リポジトリのフォルダを選びます。
2. 写真・記録・送信履歴の件数と、停止する旧自動実行を確認します。
3. 移行は旧ジョブの実行中には行いません。旧自動実行を無効化し、停止確認後に送信履歴を読み直して移します。
4. 送信済み履歴には、今はローカルに存在しない写真の名前も残します。あとから取得しても再送されません。
5. 移行後は「確認してから送る」、自動同期オフで開始します。設定を確認して有効にしてください。

旧版の記録は1日分のまとめとして残します。再取得後には同日の個別記録も表示され、内容が重なる場合があります。別施設や取得できなかった投稿を失わないため、日別まとめを自動削除しません。

元写真・旧設定・旧台帳・旧セッションは削除しません。おむかえフォトは元の写真保存先を継続使用します。移行時点で送信履歴が欠けている・内容が壊れている・同じ名前で異なる写真がある場合は、推測で処理せず止めます。同じ名前・同じ内容の重複ファイルは台帳上で1件にまとめます。

旧版を再開する場合はおむかえフォトを終了し、旧版の`setup.py schedule`で定期実行を再登録するとともに、無効化したラベルを`launchctl enable gui/$(id -u)/<ラベル>`で有効にする必要があります。おむかえフォトへの移行後に送信した写真の履歴は旧版へ自動で戻りません。単純に旧版を再開すると重複送信になるため、台帳の統合を先に行ってください。

## データの保存

- 写真・添付・記録：設定した保存先。新しい記録は`日付/記録/<投稿識別子>.json`と`.md`に保存します。投稿単位のため一部の取得失敗で別施設・別月の既存記録を消しません。
- 写真の日付：投稿日をEXIFへ書き込みます。日付が不明な画像は原本を`unknown-date`へ保存し、写真.appへの自動取り込みを保留します。
- 設定・写真の状態・送信台帳：Electronの`userData`配下`archive.sqlite`。このツールから端末外の自前サーバーへ送信しません。
- ログイン状態：`userData/sessions/*.enc`。Electron safeStorageを使用し、MacではKeychainに基づく暗号化を行います。パスワードそのものはこのツールに保存しません。利用可能な暗号化がない場合は平文保存せずエラーにします。
- みてねの有効なログイン状態は、連携有効時の選別更新で1日1回確認・更新します。失効した場合は再ログインします。
- 写真ライブラリDBは読み取り専用で開き、WALを含む最新状態を参照します。顔認識は非公開DB形式に依存するため、OS変更で対応が必要になる場合があります。

バックアップ時はおむかえフォトを終了してから、写真保存先と`userData`全体をコピーします。ログイン状態は別のMacでは再利用できない場合があり、その場合は再ログインします。おむかえフォトを削除しても写真・台帳は自動削除しません。

## 開発・試験

```bash
cd desktop
npm ci
npm run browser:install
npm run typecheck
npm test
npm run test:ui
npm run test:native
npm start
```

`npm run demo`は隔離された一時データでElectronを起動します。`npm run dev -- --port 4179`は架空データだけのブラウザプレビューです。どちらもコドモン・みてねへの実送信はしません。実アプリの操作はpreloadの限定APIからメインプロセスへ渡し、レンダラーのNodeアクセス・任意ナビゲーション・任意IPCは許可しません。

実サイトの読み取りだけを確認する開発用スクリプトもあります。実行は任意で、CIから実行しません。

```bash
CODOMON_LEGACY_DIR=/path/to/old/install npx tsx scripts/read-only-check.ts
```

既存セッションをメモリ上で使用し、直近7日分を一時フォルダへ保存・再取得して件数と重複を確認します。元セッション・台帳・写真ライブラリ・みてねの投稿は変更せず、一時保存物は削除します。

配布アプリにフルディスクアクセスを許可した後は、`CODOMON_LEGACY_DIR=/path/to/old/install node scripts/check-photos-native.mjs`で実ライブラリの読み取りと旧版の選別結果との一致を確認できます。macOSの通常起動でアプリを開き、隔離した試験データを使います。写真やアルバムは変更しません。

## 旧版を動かしたまま実データを検証する

この段階では、通常画面の「旧版から引き継ぐ」は使いません。この操作は旧自動実行を停止するため、本番切り替えを決めてから使います。

```bash
# 出力先の親ディレクトリは作成済み、出力先自体は新規または空にします。
npx tsx scripts/check-shadow-data.ts \
  --source /path/to/old/install --output /path/to/isolated-check \
  --sync --refresh-mitene --browser-path /path/to/bundled/chromium
CODOMON_SHADOW_OUTPUT=/path/to/isolated-check node scripts/check-shadow-ui.mjs
```

旧写真・記録・添付を独立コピーし、送信履歴を検証用DBへ引き継ぎます。コピーのハッシュ、元データの不変、旧ジョブの登録維持、引き継ぎと再取得の重複、旧送信済みの保持を照合します。ログイン情報はメモリだけで使い、コピー先には保存しません。旧処理が動いて元データが変化した場合は検証を失敗として、新しい空の出力先でやり直します。

検証用の配布アプリは`--test-mode`で起動し、同期・送信・写真.app操作・通常の移行を拒否します。架空のデモ画像ではなくコピーした実写真を表示します。検証用DBは本番への切り替えに流用せず、切り替え時には最新の旧送信履歴を通常の移行手順で引き継いでください。検証完了まで旧版の運用は続けます。

## 配布ファイル

```bash
npm run package:mac
```

`desktop/release/`へDMGとZIPが生成されます。Playwright用ブラウザを同梱するためサイズは大きめです。Python実行環境は含みません。

`.github/workflows/desktop.yml`はApple SiliconとIntelの各Macランナーで試験・パッケージを作る構成です。成果物をActionsへ添付するだけで、GitHub Releasesへ自動公開しません。Intelビルドの実行結果は、そのランナーで確認してから公開します。

署名・公証、完全自動更新、Windows版、iPhone管理は初版に含めません。更新ボタンはGitHub Releasesの新しい版を確認し、ダウンロードページへ案内します。

## 初版の検証結果（2026-10-02）

- TypeScript型検査、単体・移行・サービス試験51件、Playwright画面試験17件、既存Python回帰試験31件が成功。
- サブエージェントによる実装レビューを実施。増分取得の欠落、移行時の台帳競合、送信結果不明時の再送、アルバム置き換えの失敗経路を修正・検証。
- Apple SiliconのElectron本体と配布アプリで起動、限定preload、設定保存と再起動、デモ表示を確認。同梱ブラウザの起動も確認。
- 実コドモンの読み取り・繰り返し取得による件数と識別子の一致、みてねのアップロード画面の読み取り、実写真ライブラリの読み取りと旧Python版との選別一致を確認。
- 実みてねへの投稿と実写真ライブラリへの書き込みは行っていません。送信・アルバム変更の失敗経路は模擬アダプターで検証しています。Intelランナーでの実行、署名・公証、GitHub Releases公開は未実施です。
