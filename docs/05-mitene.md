# みてねへの自動アップロード

指定した人物と識別された写真を、家族アルバム みてね へ自動アップロードする。実行は [mitene_upload.py](../mitene_upload.py)。1日4回のジョブ（[03-operations.md](03-operations.md)）に組み込み済み。

**みてねプレミアム（月額590円）が必須。** ブラウザからのアップロードは有料プランの機能で、無料会員では実行できない。

## 全体の流れ

```text
コドモン取得(17:30) → 写真.app「コドモン」
                        ↓ 顔認識
                      人物別アルバム
                        ↓ 台帳との差分
                      みてねへアップロード（7/13/19/21時）
```

## アップロードの仕組み

UI操作方式を採っている。`input[type=file]` にファイルを渡し、公開範囲のボタンを押すだけ。

```text
1. みてねWeb版のアップロード画面を開く
2. set_input_files() で写真を渡す（複数可）
3. 「家族みんなに公開」ボタンを押す
4. 「N点のアップロードが完了しました」を待つ
```

### なぜUI操作方式か

内部的には署名付きURLを取得してS3へ直接送る作りですが、その仕様は公開されていません。推測で実装すると壊れやすいため、**画面操作で確実に動く方**を選びました。UI操作でも2手で完結します。

## 公開範囲

ファイルを選択すると、画面に2つのボタンが現れる。

| ボタン | 用途 |
| --- | --- |
| 家族みんなに公開 | 既定。本番はこちら |
| 管理者のみ | 検証用。家族には見えない |

`--scope "管理者のみ"` で切り替えられる。アップロード後にみてね側で公開範囲を変更することも、削除することもできる（確認済み）。

## アップロード済みの管理

**みてね側のデータは一切参照せず、ローカルの台帳 `mitene_uploaded.json` で管理する。**

```text
対象 = 指定した人物と識別された写真 − 台帳
```

iCloud共有アルバムでは「投稿するとファイル名も日時も変わる」ために投稿済み判定が不可能になった（[04-face-recognition.md](04-face-recognition.md)）。台帳方式なら相手側の仕様に一切依存しない。

### 運用コマンド

```bash
.venv/bin/python3 mitene_upload.py --login    # 手動ログイン（初回・失効時）
.venv/bin/python3 mitene_upload.py --seed     # 現状を「対応済み」として記録（送信しない）
.venv/bin/python3 mitene_upload.py --dry-run  # 対象を数えるだけ
.venv/bin/python3 mitene_upload.py            # 未アップロード分を送信
```

みてね側で写真を削除したら、台帳から該当ファイル名を消せば再送対象に戻る。

## セッションは自動で延命される

みてねのセッションは**最終アクセスから14日**のスライド式で、アクセスするたびに期限が更新される。

```text
アクセス前: 2026-08-25 22:52
アクセス後: 2026-08-25 23:51   ← 常に「最終アクセスから14日後」
```

`mitene_upload.py` は毎回この更新後のCookieを書き戻すので、**定期実行が動いている限りセッションは切れない**。送信対象が無い日も、1日1回だけページを開いて期限を延ばす（`refresh_session()`）。

そのため、再ログインが必要になるのは次の場合だけ。

- Macを**14日以上**使わなかった（長期の旅行など）
- みてね側でセッションが無効化された（パスワード変更など）

### 🔧 セッションが切れたときの復旧手順

ログに次のように出て、macOSの通知も表示される。

```text
みてね: セッションが失効しています。N 枚が未送信です。次を実行して再ログインしてください:
cd ~/Documents/Development/codomon-photo-sync && .venv/bin/python3 mitene_upload.py --login
```

**この1コマンドを実行するだけでよい。**

```bash
cd ~/Documents/Development/codomon-photo-sync && .venv/bin/python3 mitene_upload.py --login
```

ブラウザが開くので、メールアドレス・パスワードを入力し、**ワンタイムパスワード（OTP）まで完了**させる。アルバム画面に到達するとセッションが保存され、次の定期実行から自動的に再開される。未送信分は台帳に残っているので取りこぼさない。

長期間Macを離れる予定があるときは、戻ってからこのコマンドを打てばよい（事前対応は不要）。

### なぜログインだけ自動化しないのか

ログインには **reCAPTCHA と2要素認証（OTP）** がある。

- ヘッドレスでの自動ログインは reCAPTCHA に弾かれる（「セキュリティ上の問題でログインできませんでした」）
- reCAPTCHA を迂回する実装（ブラウザ指紋の偽装など）は、規約に明文が無くても運営の意思に反するため行わない

失効時にログイン画面を自動で開く仕組みも検討したが、セッションがスライド式で**失効自体がほとんど起きない**ため、複雑さに見合わないと判断して採用しなかった。

### 手動ログイン時の注意

Playwright が起動するのは **「Google Chrome for Testing」** という別アプリ。通常のChromeと見た目が似ているため、普段のブラウザでログインしても意味がない（セッションを取得できない）。ブックマークも拡張機能もない素のウィンドウが対象。

## 利用規約について

みてねの利用規約 第13条（禁止事項）に、自動化・スクレイピングを明示的に禁じる条項は無い。関連しうるのは次の一般条項のみ。

> 弊社または第三者のサーバーに負担をかける行為、もしくは、本サービスの運営やネットワーク・システムに支障を与える行為

自分の家族アルバムに自分の写真を1日数枚アップロードする用途であれば、負荷の観点で問題になる水準ではない。ただし**ログインに reCAPTCHA を置いていること自体が、自動アクセスを歓迎していない意思表示**でもある。ログインを人手で行う現在の形は、その線を越えないための設計でもある。
