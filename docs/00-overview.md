# 概要

## 目的

保育園から配信される子どもの写真を、手作業のダウンロードなしで手元に集める。あわせて写真だけでは失われてしまう文脈（その日の活動記録の本文）も保存する。

## 動作

1. コドモン保護者版（`parents.codmon.com`）に自動ログイン
2. 内部REST APIから直近30日分のタイムラインを取得
3. 写真をダウンロードし、投稿日ごとのフォルダに保存（EXIFに投稿日時を埋める）
4. 全種別の本文を `記録.md` / `posts.json` として保存
5. 添付ファイル（PDF等）を `添付/` へ保存
6. 未取り込みの写真を写真.appの「コドモン」アルバムへ取り込む
7. 顔認識で指定した人物と識別された写真を人物別アルバムへ反映（[04-face-recognition.md](04-face-recognition.md)）
8. 未アップロード分をみてねへ送信（[05-mitene.md](05-mitene.md)）

launchd により毎日17:30と21:00に自動実行される。iCloud写真が有効なら、アルバムは iPhone/iPad からも見られる。

写真.appへの取り込みを止めたい場合は `CODOMON_NO_PHOTOS=1` を指定する。

## 写真の日付について

配信画像は CloudFront のリサイズで **EXIF が完全に除去されている**。そのまま保存すると写真.appが「取り込んだ日」を撮影日として扱ってしまい、全写真が実行日に固まる。

これを避けるため、ダウンロード時に投稿日時を EXIF (`DateTimeOriginal`) に書き込んでいる。時刻は投稿の `delivery_start_datetime` を使うので、同じ日の中でも正しい順序で並ぶ。

## 保存されるもの

```text
~/Pictures/codomon/2026-08-05/
├── 142228753-IMG_0260.jpeg
├── ...（写真7枚）
├── 添付/
│   └── 12345-8月月初のおたより.pdf
├── 記録.md
└── posts.json
```

### 記録.md の形式

```markdown
# 2026-08-05 の記録

## [活動記録] 散歩　根津神社

- 公開範囲: 参加者にのみ公開 / 配信: 2026-08-05 11:18:21

（本文）

### 写真 7枚
- ![](142228753-IMG_0260.jpeg)
```

画像リンクは同フォルダの実ファイルを相対参照するため、Markdownビューアで開けば本文と写真が一緒に表示される。

### posts.json

タイムラインAPIの生データ。`記録.md` が拾っていない項目が将来必要になっても取りこぼさないための保険。

## 取得方式

| 対象 | 方式 |
| --- | --- |
| タイムラインのメタデータ | 毎回全量取得（直近30日・数リクエスト） |
| 写真 | **差分のみ**。保存先にファイルがあればHTTPリクエストも行わない |
| 記録.md / posts.json | 毎回上書き再生成（通信は増えない。園側の本文修正に追随する） |

写真のファイル名は投稿ID付きで一意（`142228753-IMG_0260.jpeg`）のため、名前の一致だけで既取得を判定できる。ハッシュ計算もダウンロードも不要。

## 対象と対象外

| 種別 (`timeline_kind`) | 件数 | 表示名 | 本文フィールド |
| --- | --- | --- | --- |
| `comments` | 446 | 連絡帳 | `content` |
| `topics` | 350 | お知らせ | `content` |
| `activities` | 71 | 活動記録 | `overview` |
| `bills` | 1 | 請求情報 | 明細は `data` |

**園から届く情報はすべて保存する。** 当初は写真の付く `activities` / `topics` だけを対象にしていたが、**連絡帳446件（体温・食事・睡眠・家庭からの連絡）がまるごと抜けていた**。写真の有無で判断したのが誤りだった。

### 添付ファイル

お知らせ等には `file_url`（PDF・Word）が付く。園だより・行事予定・感染症のお知らせなどで、**退園後は入手できなくなる**ため保存する。

配信元のホストによっては、**ステータス200が返るのに中身がHTML**というケースがあるため、`content-type` を確認してから保存している。日本語ファイル名はURLエンコードされているのでデコードして戻す。

「写真共有・販売」（購入が必要な写真）は対象外。自動化が自動課金に直結するリスクを避けるため、関連エンドポイントには一切アクセスしない。

## 制約

- **画像は500×375が上限**。無料枠の仕様で、原寸は写真販売の購入フローでしか入手できない（詳細は [01-architecture.md](01-architecture.md)）
- **30日より古い投稿は取得対象外**。過去分が必要な場合は `DAYS_TO_CHECK` を一時的に大きくして1回実行する
- 園が同じファイル名で写真を差し替えた場合、更新に気づかない（内容ハッシュではなくファイル名で判定しているため）
